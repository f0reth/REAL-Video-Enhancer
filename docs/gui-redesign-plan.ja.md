# REAL Video Enhancer GUI 全面刷新計画

作成日: 2026-11-03  
状態: 工程1の基盤実装・Windows CPU検証済み（他工程とGPU／他OS検証は継続）  
最優先事項: モデル・画質設定を細かく調整する操作性

## 1. 目指す体験

**「同じ場面を見ながら、モデルと出力画質を調整し、設定の違いを比較してから書き出す」作業を一画面で完結させる。**

主な利用者は、モデル名やエンコード設定を自分で選びたいユーザーとする。詳細項目を隠すだけの簡易化ではなく、関連する設定の集約、正確な数値入力、比較、再現性を中心に設計する。

基本の操作は次の順序にする。

1. 動画を追加し、確認したい時刻・区間を選ぶ。
2. 復元・補間・拡大のモデルと設定を調整する。
3. 短い区間を試し書き出しし、入力／処理後、設定A／Bを比較する。
4. 出力形式と圧縮画質を確認し、設定を固定したジョブとしてキューに追加する。
5. 処理結果を確認し、必要なら設定を複製して再調整する。

刷新対象はGUIと、それを支える設定・ジョブ・プレビュー・実行制御である。推論アルゴリズムの全面変更は含めない。

## 3. 画面構成

アプリの主画面を「編集」「キュー」「モデル・実行環境」「アプリ設定」の4つに整理する。起動時は編集画面を開き、更新履歴や支援リンクはヘルプへ移す。

### 編集画面の配置案

```text
┌─────────────────────────────────────────────────────────────────────┐
│ 編集 | キュー(3) | モデル・実行環境 | 設定           GPU / 実行状態   │
├──────────────┬──────────────────────────┬───────────────────────────┤
│ 入力動画     │ 比較ビュー               │ 処理・出力設定            │
│ + 動画を追加 │ 入力 / 処理後 / A・B      │ 設定内検索 / プリセット   │
│              │                          │                           │
│ clip01.mp4   │ 100%表示・拡大・パン      │ ▾ 復元                    │
│ clip02.mkv   │ 同じ位置・倍率で比較      │ ▾ フレーム補間            │
│              │                          │ ▾ アップスケール          │
│ 入力情報     │ 時刻 / 区間指定           │ ▾ 出力・エンコード        │
│ 解像度・FPS  │ [試し書き出し] [Aに保存] │ ▾ GPU・推論設定           │
├──────────────┴──────────────────────────┴───────────────────────────┤
│ 出力: 解像度 / FPS / 形式 / 保存先   [キューへ追加] [書き出す]        │
└─────────────────────────────────────────────────────────────────────┘
```

左右の幅は `QSplitter` で調整し、プレビューと設定欄の広さをユーザーが選べるようにする。左の入力一覧は折りたたみ可能にする。右の設定欄だけを縦スクロールさせ、出力要約と実行ボタンは常に表示する。

「書き出す」は現在の設定を検証してジョブを作成し、空きがあれば開始する。既に処理中なら待機キューへ追加したことを明示する。キュー追加と直接実行で設定確定の経路を共通にする。

## 4. モデルと画質の調整仕様

### 4.1 モデル選択

長いコンボボックスを、検索・絞り込みができるモデル選択パネルへ置き換える。

- 検索対象: 名前、モデル系列、用途、アーキテクチャ。
- 絞り込み: 処理種別、利用可能なバックエンド、導入済み、お気に入り。
- 一覧の列: 名前、用途、モデル倍率、対応環境、導入状態。
- 選択時の詳細: モデルの説明、既知の制約、ファイル、実行可能な設定。
- 速度・VRAMは実測値がある場合に条件を添えて表示する。未測定のモデルに順位や必要容量を推測で付けない。
- 未導入でも設定を組めるようにし、取得が必要なことを表示する。実行準備時にダウンロード量と進捗を確認できるようにする。

内部では表示名をIDとして使わず、`ModelSpec` にモデルID、処理種別、対応バックエンド、倍率、取得先、対応オプションをまとめる。画面ごとに対応判定を重複実装しない。

カスタムモデルも初版の対応範囲に含める。現行のPyTorch／TensorRT向けローカルモデルとNCNNモデルを能力棚卸しの対象にし、対応確認済みの実行経路を維持する。

- 同梱モデルと同じ `ModelSpec` で扱い、取得元はダウンロード先またはローカルファイル参照のどちらかとする。NCNNなど複数ファイルからなるモデルは一組として登録する。
- 登録時に表示名とは独立したモデルIDを発行し、必要なファイル、内容のハッシュ、倍率、対応バックエンド・オプションを記録する。倍率や能力は読み取れる情報と実行経路から検証し、判定不能なモデルを推測で実行可能にしない。
- ジョブにはモデルIDだけでなく、登録時に検証したファイル情報と能力情報を固定する。実行準備時に消失・内容の変更を検証し、変更されていればジョブを失敗として理由を表示する。再登録したモデルを使うには設定を明示的に更新する。
- 登録解除は一覧からの削除だけとし、ユーザーが指定したモデルファイルを削除しない。旧モデル一覧の移行は行わず、必要なローカルモデルは新形式で再登録する。

デブラーは現在メイン画面で非表示になっている。定義があるだけで公開機能とは扱わず、対応モデルと実行経路を確認してから表示を決める。未実装のDirectMLも選択肢として公開しない。

### 4.2 処理設定

| グループ | 編集項目 | 操作上の工夫 |
| --- | --- | --- |
| 復元 | 圧縮劣化除去、ノイズ除去、対応確認済みのデブラー、各モデル | 個別ON/OFF、モデル説明、設定単位の初期値復帰 |
| フレーム補間 | モデル、倍率、出力FPS、スローモーション、シーン検出、対応するEnsemble等 | 入力FPSからの変化、出力尺への影響を即時表示 |
| アップスケール | モデル、最終倍率、出力解像度、タイル設定 | モデル本来の倍率と、後段リサイズを含む最終倍率を区別 |
| 出力・エンコード | 保存先、命名、コンテナ、映像・音声・字幕設定 | コーデックに合う入力欄と組み合わせ検証 |
| GPU・推論 | デバイス、バックエンド、精度、TensorRT最適化等 | 対応環境だけ編集可能にし、非対応理由を表示 |

数値は直接入力を基本とし、連続的な調整が有用な項目にはスライダーを併設する。単位、範囲、初期値、変更済み表示を統一する。検索すると該当グループを開き、ラベルと説明の両方を検索する。

モデル側に強度パラメーターがない処理には、ノイズ除去強度やシャープ量などのスライダーを新設しない。初版の処理順序は現在のバックエンドに合わせて固定し、実際の適用順序を画面に表示する。自由なノード編集や並べ替えは対象外とする。

補間倍率と出力FPSは同一の設定から算出する。任意FPS入力を提供する場合も、バックエンド・モデルが対応する倍率へ変換できる範囲に制限し、丸めや制約を表示する。

### 4.3 エンコード画質

「High」などの抽象的な品質選択だけに依存せず、実際に使うパラメーターを表示する。

- CRFに対応するエンコーダーではCRF、CQに対応するものではCQを編集する。
- ProResではプロファイル、ロスレス専用形式では実際に有効な項目を表示する。
- エンコーダー変更時に非対応値を黙って流用しない。変更される値を示し、有効な初期値へ設定する。
- 速度プリセットもエンコーダーが受け付ける値に対応付ける。
- 画素形式・ビット深度・HDRの入力値と実効出力値を分けて表示する。
- 音声・字幕のコピー可否をコンテナと合わせて検証する。
- FFmpeg引数は読み取り専用で確認・コピーできるようにする。初版は構造化した設定を唯一の編集元とし、自由入力コマンドとの二重管理を避ける。

品質スケールをエンコーダー間で同一視しない。詳細な値を持てるよう、`FFMpegCommand` と全呼び出し元を同じ変更で更新する。

## 5. 比較プレビュー

最初のリリースでは、短区間の試し書き出しと、結果動画からの静止フレーム比較を必須にする。動画の同期再生は次段階とする。

1. 時刻と区間を選ぶ。既定区間は5秒とし、入力尺を超えないようにする。
2. 現在の設定を確定して試し書き出しする。設定変更のたびにGPU処理を自動実行しない。
3. 入力／処理後を並べて表示、または境界スライダーで比較する。
4. 表示位置と倍率を同期し、等倍表示で輪郭・ノイズ・圧縮劣化を確認する。
5. 結果Aを保持し、設定を変更して結果Bを生成する。A／Bの設定差分を併記する。

「推論の処理結果」と「エンコード後の画質」を区別する。初版の比較は実際の出力設定で書き出した結果を使い、GPU処理中の最新フレームは進捗確認用として明記する。

プレビューには通常ジョブと同じ設定型・コマンド生成を使い、区間と出力先だけを変える。通常キューを消去しない。GPU実行は初版では直列とし、本処理中のプレビューは待機または取消できるようにする。

補間・スローモーションの前後はフレーム番号ではなく対応する入力時刻で比較する。中間フレームには元動画上の完全に同じフレームがないことも表示する。解像度が違う比較では拡大方法を統一し、比較条件を示す。

HDRは通常のSDR表示と区別する。比較用にトーンマップする場合は明記し、HDRの色再現を保証する表示とは扱わない。領域クロップによる推論は文脈や境界条件が変わるため初版では行わず、生成結果の拡大・パンで確認する。

プレビュー結果には設定・入力情報・区間を記録する。設定変更後は「表示中は前の設定の結果」と明示する。保存容量の上限を設け、自動削除はアプリが生成したプレビュー用ファイルに限定する。「Aに保存」「Bに保存」は比較結果の保持操作とし、保持中・表示中・生成中の結果は自動削除の対象外にする。保護されていない古い結果から削除する。

保護対象だけで上限に達する場合は新規生成を開始せず、保持の解除、不要な結果の明示的な削除、上限変更を選べるようにする。生成中に上限へ達した場合は生成を取消し、新規生成分の部分ファイルだけを削除して、既存のA／Bを保持する。実際のディスク空き容量不足も同じ扱いにする。保持解除と削除は別操作にし、比較対象が失われる削除では対象を明示する。

## 6. 設定、プリセット、ジョブのルール

### 設定の所有範囲

- **アプリ設定:** 表示、通知、既定保存先など。画質・推論の既定値は新規編集開始時にコピーする。
- **編集中の設定:** 対象動画の処理、出力、実行環境。編集だけで待機中のジョブは変えない。
- **ジョブ設定:** キュー投入時に画質・推論・エンコード設定をすべて固定する。
- **実行中の状態:** 進捗、実効精度、処理段階、エラー。要求した設定とは別に記録する。

待機ジョブは「編集」で設定を読み込み、「ジョブを更新」で明示的に置き換える。実行中のジョブは変更せず、複製して次の試行を作る。GPUやモデルが利用できなくなった場合は再検証し、別モデルや別バックエンドへ黙って切り替えない。

### プリセット

初版は名前付きの全体プリセットを保存・複製・削除できるようにする。保存対象はモデル、処理、画質設定とし、入力動画、絶対出力先、特定PCのGPU IDは含めない。モデルの部分プリセットや外部共有機能は後回しにする。

適用前に変更内容と非対応項目を確認できるようにし、適用後に変更した項目を表示する。「最後に適用した設定へ戻す」と「初期値へ戻す」は別操作にする。

### 保存形式とリポジトリ方針

型付きデータをJSON等の単純な現行形式で保存し、GUIの表示文字列やウィジェット名を内部形式に使わない。書き込みは一時ファイルからの置換で行う。

AGENTS.mdに従い、旧設定・旧プリセットの移行や互換ラッパーは作らない。新形式への切替時にアプリ設定の再設定が必要なことを案内する。動画・モデル重みは保存形式変更の対象外とし、削除しない。旧キャッシュも移行せず、新しいキャッシュ規則を使う。

## 7. キュー、実行状態、エラー

キューは動画名だけでなく、処理概要、出力解像度／FPS、保存先、状態を表形式で表示する。並べ替え、待機ジョブ編集、複製、取消、失敗ジョブ再試行を提供する。完了・失敗の行は確認できるまで残す。再起動をまたぐキュー復元は初版の必須要件にしない。

状態は「待機 → 準備 → 実行 → 完了」を基本に、「一時停止」「取消中」「取消済み」「失敗」を明示する。準備中にはモデル取得、エンジン構築、読み込みなどの段階を表示し、終端状態から戻す場合は再試行として新しい実行記録を作る。

- 全体と現在ジョブの進捗を分ける。エンジン構築中は不確かな残り時間を表示しない。
- 一時停止できる段階でだけ操作を有効にし、要求受付と停止完了を区別する。
- 一時停止中は再開に必要なFFmpegストリーム・共有メモリを保持し、取消・正常終了・異常終了時に解放する。工程1で確定した契約と検証結果は [実装・検証記録](gui-redesign/phase-1-results.ja.md) を参照。
- 取消時はバックエンドだけでなく子FFmpegプロセスと共有メモリの解放まで扱う。
- 失敗理由、変更候補、ログへの導線をそのジョブに残す。エラーを一時通知だけで消さない。
- 出力パス衝突、書き込み権限、必須モデル、対応オプションをジョブ確定時と実行直前に検証する。
- 入力動画と同じファイルへの出力は禁止する。パスの正規化に加え、既存ファイルはシンボリックリンクやハードリンクを含む同一性を確認する。待機・準備・実行・一時停止中の通常ジョブには同じ出力先を予約させない。プレビューは専用の一意な出力先を使う。
- 既存出力の置換はジョブごとに対象を示して明示的に許可する。許可は確認したファイルに限り、実行までに対象が追加・変更されていれば再確認待ちにする。再試行で過去の置換許可を自動再利用しない。
- 書き出しは出力先と同じディレクトリのジョブ専用一時ファイルへ行い、バックエンドの完了通知と成果物検証が成功してから最終パスへ確定する。確定直前にも衝突条件を確認し、無許可の上書きを防ぐ。置換を許可した既存出力も確定までは保持する。
- 失敗・取消ではその実行が作った一時ファイルだけを削除し、入力・既存出力に触れない。削除や確定に失敗した場合は完了扱いにせず、残った一時ファイルのパスと理由をジョブに表示する。
- 現行のNCNN終了コードの特例は実機で再評価する。一般的なクラッシュコードを無条件で成功扱いせず、バックエンドの完了通知と成果物検証も含めて成功条件を定義する。

## 8. 技術構成

### 採用方針

**既存のPySide6 / Qt Widgetsを継続し、画面と状態管理を作り直す。** 現行のPython実装、デスクトップ配布、推論プロセスを活用でき、GUI刷新に集中できるためである。Web化や別GUI基盤への移行は今回の必須条件にしない。

画面は小さなPythonのWidgetクラスとQtのレイアウトで構成する。現行の巨大な `.ui` とメインウィンドウへのウィジェット集約を解消する。新旧画面を恒久的に選択できる仕組みは作らず、切替完了時に旧定義と不要な生成手順を削除する。

役割は次の範囲に絞る。汎用プラグイン基盤や独自の巨大な状態管理フレームワークは作らない。

| 責務 | 内容 |
| --- | --- |
| 画面 | 編集、比較、キュー、環境、アプリ設定の表示と入力 |
| データ | `VideoInfo`、`ProcessingSettings`、`EncodingSettings`、`ExecutionSettings`、`Job`、`ModelSpec` |
| 実行制御 | 検証、ジョブ状態遷移、モデル取得、プレビューと本処理の直列実行 |
| インフラ処理 | 設定保存、モデル一覧、FFmpeg引数生成、バックエンドプロセス、画像受け取り |

モデル一覧とキューにはQtのモデル／ビューを使う。`QAbstractTableModel` は表データ用の標準APIであり、ウィジェットと並行する独自配列の手動同期を減らせる。[Qt公式資料](https://doc.qt.io/qtforpython-6.8/PySide6/QtCore/QAbstractTableModel.html)

バックエンド起動・標準出力受信・終了検知は `QProcess` の非同期シグナルで扱う。GUIスレッドで `waitForFinished()` などの待機を行わない。[Qt公式資料](https://doc.qt.io/qtforpython-6.8/PySide6/QtCore/QProcess.html)

### フロントエンド／バックエンド境界

- ジョブ設定から引数を生成する処理は、副作用を持たない一か所にまとめる。コマンド生成中にモデルを取得したり、ジョブ設定を書き換えたりしない。
- 現行CLIの必要な引数を整理し、開始・終了時刻を含めて全設定を明示的に渡す。引数変更時は全呼び出し元を同時に更新する。
- 進捗はstdoutのJSON Lines、診断ログはstderrに統一する。`stage`、処理済み数、総数、FPS、完了、エラーの通知形式を定義する。
- バックエンド内部の既存printや外部ライブラリの出力も整理し、JSON出力に混入させない。古いログ解析との互換分岐は残さない。
- 大きなプレビュー画像は既存の共有メモリ方式を整理して使う。画像と通知を同じ転送方式に詰め込まない。
- ウィジェット更新はGUIスレッドに限定し、プレビュー更新頻度を制限する。終了・取消・異常終了の全経路で所有する共有メモリを解放する。
- バックエンドの能力は環境検出結果とモデル定義から求める。表示名の文字列比較で対応を決めない。

バックエンド修正はCLI・進捗・能力通知など、GUIの契約に必要な範囲に絞る。実際にサポートされているOS／バックエンドの組み合わせを棚卸しし、その機能を維持する。

## 9. 見た目と操作の統一

- ダークテーマを初版の基準にし、背景、枠、文字、強調、警告、余白、文字サイズを共通定義する。
- 大きな角丸・空白を減らし、詳細項目を一覧しやすい密度にする。処理中のプレビューでは画像領域を優先する。
- ナビゲーションと実行操作にはテキストを付け、アイコンだけの意味解釈を減らす。
- 正常、選択、無効、警告、失敗を色だけで区別しない。フォーカス表示とキーボード操作を設ける。
- 出力解像度、FPS、ビット深度、保存先、未導入モデルを実行前の要約に表示する。
- 非対応の設定には理由を添える。モデル変更で無効になった値を裏で持ち越さない。
- 日本語ラベルを前提に幅を確認し、文字列を翻訳可能な形で管理する。多言語翻訳の完了は別工程とする。
- 1366×768、1920×1080、Windows拡大率100／150／200%を確認し、対応するLinux・macOSでも主要画面を確認する。

## 11. 検証と受け入れ条件

### 操作体験

1. モデル検索から詳細設定、試し書き出しまで、アプリ設定ページへ移動せず操作できる。
2. CRF／CQ等の実際の設定値と、出力解像度・FPSを実行前に確認できる。
3. 同一区間でA／Bを生成し、同じ拡大率・位置で比較し、設定差分を読める。
4. プレビューを何回実行しても通常キューが失われない。
5. 待機ジョブの設定を編集・複製でき、編集前後の対象が分かる。
6. 非対応設定は実行前に理由付きで検出される。未導入モデルは取得手順へ進める。

### 再現性と実行制御

7. キュー投入後に全体の既定値を変更しても、既存ジョブの画質・推論設定と生成引数が変わらない。
8. プレビュー指定区間がCLIまで渡り、代表動画で出力尺と対応時刻が合う。
9. 成功、失敗、ユーザー取消を区別し、失敗した出力を完了扱いしない。
10. 取消・終了後に子プロセスや所有する共有メモリが残らず、続けて別ジョブを実行できる。
11. 処理中・ダウンロード中・環境検出中もウィンドウ移動と取消操作に応答する。
12. ユーザー動画と既存モデル重みをGUI刷新や設定リセットで削除しない。

13. 入力と同一の出力先、実行待ちジョブ間の出力先重複を拒否する。既存出力はジョブ単位の許可なく置換しない。
14. 失敗・取消でも既存出力が保持され、成功した一時出力だけが最終パスへ確定する。確認後の出力先変更や確定失敗を検出し、再確認または失敗として表示する。
15. 対応するカスタムモデルを登録して実行でき、倍率・対応環境が表示される。登録後のファイル消失・置換を実行前に検出し、登録解除で重みを削除しない。
16. 保存上限に達しても保持中・表示中のA／Bを自動削除しない。新規生成を停止する場合は理由と解消操作を表示し、生成途中の容量超過でも既存比較結果を保持する。

### 検証方法

- 単体検証: 設定検証、モデル能力判定、数値からFFmpeg引数への変換、ジョブ固定、出力パス衝突・同一ファイル判定・置換許可、カスタムモデルのファイル変更検出、プレビュー保持と容量制御、状態遷移。
- 軽量な結合検証: 小さな擬似バックエンドでJSON通知、分割受信、標準エラー、起動失敗、異常終了、取消を確認する。
- 実動画検証: 補間のみ、拡大のみ、復元との組み合わせ、複数動画、23.976／29.97FPS、音声・字幕、10bit／HDR、途中失敗を代表ケースとして確認する。
- プレビュー検証: 本処理と同じ設定が渡ることを確認する。時間方向のモデル特性上、区間境界の影響があるため、全編処理とのビット単位一致を要件にしない。
- 実機検証: 利用可能な各サポート環境で短いスモーク処理を実施する。未検証のOS／GPUは確認済みとして扱わず、検証表に残す。
- ファイル操作検証: 一時ディレクトリで、同一入力・出力、ジョブ間重複、確認後の出力先変更、成功時の確定、失敗・取消・確定失敗を再現し、既存ファイルの内容が保護されることを確認する。小さな保存上限でA／B保持と生成中の容量超過も検証する。
- 配布検証: 現行の配布方式を確認し、新UIのリソース、Qtモジュール、起動経路を含めてビルドを試す。

## 12. 最初に着手する具体的な範囲

最初の作業単位は、**設定の所有範囲と新編集画面のワイヤーを確定し、一動画・一モデルの実行経路を新しいジョブ型で通すこと**とする。

その時点で「モデル選択」「エンコードの数値入力」「出力要約」「短区間プレビュー」の配置をレビューし、同時にキュー固定と区間引数の検証を終える。以降はその経路に対応済みの処理と画面を加え、最終工程で旧GUI・旧設定読み書き・旧ログ解析・不要なビルド生成処理を削除する。
