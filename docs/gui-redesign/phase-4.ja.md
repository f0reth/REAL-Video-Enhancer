# 工程4: キューと環境画面

状態: 未着手  
目安: 4〜6日  
上位仕様: [GUI全面刷新計画](../gui-redesign-plan.ja.md)

## 目的と開始条件

工程1の実行制御と工程2〜3のジョブ作成経路が利用できること。

この工程の成果を次工程へ渡す。工程間で契約を変更した場合は、上位仕様と関係する工程計画・全呼び出し元を同時に更新する。

## 作業順序

工程1の [実装・検証記録](phase-1-results.ja.md) の状態・出力予約・モデル登録契約を引き継ぐ。再試行では新しい `Job` を生成し、以前の置換許可を再利用しない。登録解除は `ModelRegistry.remove()` で参照だけを削除する。

1. Jobを唯一のデータ源としてQAbstractTableModelでキューを表示する。概要・保存先・状態・進捗・失敗理由を表示し、完了行を確認まで保持する。
2. 待機ジョブの並べ替え・編集・明示更新・複製・取消を実装する。実行中の設定変更は禁止し、再試行は新しい実行記録と置換許可確認を作る。
3. 準備段階、要求受付と一時停止完了、取消中、再確認待ちを可視化する。全体と現在ジョブの進捗を分け、ログと残存一時ファイルへの導線を設ける。
4. 環境画面でGPU・バックエンド・導入状態を表示する。未導入モデルの取得量・進捗・失敗を表示し、検出や取得中も操作へ応答する。
5. カスタムモデルの登録・詳細・登録解除を基盤へ接続する。ファイル消失・内容変更時は理由と再登録・ジョブ更新の操作を示す。
6. 初回セットアップとアプリ設定を接続する。既定値は新規編集時にコピーし、リセットは一回の保存で完了する。モデルやバックエンドを黙って切り替えない。

## 成果物

キュー画面、環境画面、初回セットアップ、アプリ設定、ジョブ単位のエラー表示。

## 検証と完了条件

受け入れ条件5〜7、9〜15を画面経由で確認する。処理・取得・検出中の応答性、編集対象の識別、再試行の新規記録、カスタムモデル解除後の重み保持を検証する。

検証結果には対象環境・実施内容・結果・未解決事項を記録する。計画書の作成だけで実装や検証を完了扱いにしない。

## 対象外・共通制約

旧設定・プリセット・キャッシュの移行、互換ラッパー、恒久的な新旧GUI併存は行わない。ユーザー動画・モデル重みは削除しない。同期動画再生、キューの再起動復元、プリセット共有、複数GPU同時実行、自由な処理グラフは初版の対象外とする。
