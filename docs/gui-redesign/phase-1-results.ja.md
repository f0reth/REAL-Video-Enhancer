## 実装した基盤

| 所有者 | データ／責務 | 実装 |
| --- | --- | --- |
| アプリ | 型付きの既定値。現行JSONだけを一時ファイルから置換保存 | `src/Settings.py`, `src/atomic.py` |
| 編集画面 | 現在の入力と設定からスナップショットを作る。モデル取得はしない | `MainWindow.getCurrentRenderOptions()` |
| ジョブ | `VideoInfo`, `ProcessingSettings`, `EncodingSettings`, `ExecutionSettings`, `ModelSpec` を含む変更不可の `RenderOptions` | `src/Jobs.py` |
| 実行記録 | 状態、進捗、実効値、エラー、診断ログ、出力予約 | `Job`, `src/Execution.py` |
| モデル登録 | UUID、必要ファイル一式、SHA-256、実ローダーが求めた倍率、対応バックエンド | `src/ModelSpec.py`, `backend/model-probe.py` |
| 出力 | 入力との同一性、出力予約、ジョブごとの置換許可、一時出力、検証、確定 | `src/Output.py` |

`RenderOptions` のプロパティ／setter群、実行時に全体設定を読むコマンド生成、文字列正規表現による進捗解析、処理スレッドからのウィジェット更新、固定名の共有メモリを削除した。エンコード設定は数値品質値・実プリセット・プロファイルを持ち、引数は読み取り専用表示と同じ設定から生成する。画面の数値入力への置換は工程2で行う。

通常処理とプレビューは同じ `Executor` を使う。プレビューは一意な出力先を持つ別ジョブで、通常キューを消去しない。終端状態の通常ジョブは一覧に残る。既存画面はこの基盤へ接続済みで、新旧実行経路の切替機能は設けていない。

モデル取得・ローカルファイル照合はワーカースレッド、モデル検査と推論・成果物検査は `QProcess` で実行する。大きな出力ファイルの指紋計算・確定処理もGUIスレッド外で行う。GUIに `waitForFinished()` やプロセスの `wait()` は置かない。

## 状態と通知

基本経路は `waiting → preparing → running → finalizing → completed`。

- 一時停止は `running → pausing → paused`。推論ループがフレーム境界で要求を確認してから停止完了を通知する。
- 一時停止中は、再開に必要なFFmpegストリーム・共有メモリ・出力予約を保持する。**元の工程1手順7の「一時停止で解放」は、再開可能な停止と整合しないためこの契約に明確化した。** 取消・正常終了・異常終了では解放する。
- 取消は `cancelling → cancelled`。取消要求が出力確定の後に届いた場合は、確定済みの成果物を取消扱いにしない。
- 出力が確認時から変化した場合は `awaiting_replacement`。許可はその時点のファイルID・サイズ・更新時刻・SHA-256に限定する。
- 成果物検査後に確定できない場合は `finalize_failed`。一時出力と予約を保持し、再試行／取消を選べる。残存ファイルのパスはエラーに残す。
- 再試行で以前のジョブを再利用しない。工程4の再試行UIは新しい `Job` と新しい予約を作成すること。

推論のstdoutはUTF-8のJSON Lines専用。Pythonのprintとネイティブライブラリのstdoutはstderrへ隔離する。通知は `stage`, `progress`, `effective`, `paused`, `resumed`, `completed`, `error`, `cancelled`。モデル検査は追加で `model` を返す。`progress` は `processed`, `total`, `fps`, `eta` を持つ。分割されたUTF-8、複数行の一括受信、末尾の不完全行を扱う。環境一覧・動画情報・バージョンの検査用CLIは、それぞれの専用出力契約を維持する。

正常終了コードだけでは成功にしない。完了通知に加え、FFmpegによる出力動画のデコードと1フレーム以上の確認が必要。NCNNのクラッシュコードを成功扱いする特例は撤去した。

## 出力保護

入力と出力は正規化パスおよび既存ファイルの同一性で確認し、ハードリンク経由の入力上書きも禁止する。出力先がシンボリックリンクの場合も拒否する。投入時に保存先の書き込みを確認し、同じ出力先を予約できないようにする。

出力先と同じディレクトリの `.rve-*` 一時ファイルへ書き込み、成果物検査後に確定する。置換対象は確定直前まで保持する。置換時はいったん専用退避先へ移し、指紋を再確認してから、新しい対象が存在した場合に失敗する操作で公開する。競合や権限エラーでは元ファイルを復元する。復元先にも競合があれば退避ファイルを保持してパスを記録する。

Windowsでは存在する宛先を置換しないrenameを使用する。POSIXでは同一ファイルシステム内のhard linkを使うため、hard link非対応の保存先では安全に確定失敗となる。Linux／macOSの実ファイルシステム検証は未実施。

Windowsのバックエンドは子FFmpegを含むJob Objectに所属し、バックエンドのクラッシュ・強制終了でも子を終了させる。POSIXでは専用プロセスグループを終了させる。共有メモリは実行ごとに一意な名前で作成し、GUI側の所有者が解放する。

## 保存形式の切替

`settings.txt` の読み込み・移行は行わない。現行設定は `settings.json`、ローカルモデル参照は `models.json`。旧設定は再設定し、旧カスタムモデルも既存ファイルを指定して再登録する。旧ファイル・動画・重みは削除しない。

現行JSONを手動編集して不正にした場合は、そのJSONを退避して既定値から設定し直す。キューの再起動復元は実装しない。
