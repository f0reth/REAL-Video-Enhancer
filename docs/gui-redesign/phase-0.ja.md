# 工程0: 仕様・能力棚卸し

状態: 未着手  
目安: 3〜4日  
上位仕様: [GUI全面刷新計画](../gui-redesign-plan.ja.md)

工程1で基盤に必要な設定所有範囲・能力・状態遷移を先行確定した。内容は [工程1 実装・検証記録](phase-1-results.ja.md) を参照。本工程全体のワイヤー・実機棚卸しを完了扱いにはしない。

## 目的と開始条件

全体計画を読み、現行コードを確認できること。

この工程の成果を次工程へ渡す。工程間で契約を変更した場合は、上位仕様と関係する工程計画・全呼び出し元を同時に更新する。

## 作業順序

1. 現行の画面・設定・CLI・配布経路を追い、機能ごとの呼び出し元とバックエンド対応を表にする。デブラーとDirectMLは定義の存在だけで公開対象にしない。
2. OS／GPU／バックエンドの対応表を作り、実装上の対応と実機での確認を別欄にする。PyTorch／TensorRT／NCNNのカスタムモデルも含める。
3. VideoInfo、処理・エンコード・実行設定、Job、ModelSpecの項目と所有範囲を決める。モデルID、ローカルモデルのハッシュと能力取得、ジョブ固定の契約を記録する。
4. 編集・キュー・環境・設定のワイヤーを作る。モデル検索、数値品質入力、出力要約、短区間プレビュー、A／B保持、上書き確認の操作を確定する。
5. 出力予約・一時出力・確定・取消、プレビュー容量上限、再確認待ちを含む状態遷移と操作可否を決める。
6. 代表動画と検証環境を選び、各受け入れ条件の担当工程を確認する。未知の制約を調査課題として残し、全工程の見積もりを更新する。

## 成果物

現行機能表、能力表、設定項目表、画面ワイヤー、状態遷移表、代表動画一覧、改訂見積もり。

## 検証と完了条件

全体計画の受け入れ条件1〜16に実装・検証工程が対応する。未確定事項には解決する工程を付け、基盤実装に必須の契約は確定する。

検証結果には対象環境・実施内容・結果・未解決事項を記録する。計画書の作成だけで実装や検証を完了扱いにしない。

## 対象外・共通制約

旧設定・プリセット・キャッシュの移行、互換ラッパー、恒久的な新旧GUI併存は行わない。ユーザー動画・モデル重みは削除しない。同期動画再生、キューの再起動復元、プリセット共有、複数GPU同時実行、自由な処理グラフは初版の対象外とする。
