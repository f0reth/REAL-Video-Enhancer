# 工程1: 設定と実行の基盤

状態: 基盤実装・Windows CPU検証済み（GPU／他OS実機検証は未実施）  
目安: 5〜7日  
上位仕様: [GUI全面刷新計画](../gui-redesign-plan.ja.md)

## 目的と開始条件

工程0の設定所有範囲・能力表・状態遷移が確定していること。

この工程の成果を次工程へ渡す。工程間で契約を変更した場合は、上位仕様と関係する工程計画・全呼び出し元を同時に更新する。

## 作業順序

1. 型付き設定とジョブのスナップショットを実装する。既定値・編集中の設定・固定済みジョブ・実効状態を分離し、現行形式だけを一時ファイルから置換保存する。
2. まず一動画・一モデルで設定→引数生成→起動→進捗→完了／取消を通す。開始・終了時刻もCLIへ渡し、短区間の出力尺を確認する。
3. ModelSpecと能力判定を実装する。ローカルモデルは必要ファイル一式、ハッシュ、倍率を検証して登録し、ジョブ実行前に消失・変更を検出する。登録解除はファイルを削除しない。
4. 全設定から副作用なしで引数を生成する。モデル取得・環境検出・エンジン構築は非同期の準備段階へ分離し、通常処理とプレビューを一つの直列実行制御に接続する。
5. JSON Linesの進捗とstderrの診断ログを定義し、全出力元と呼び出し元を更新する。QProcessで分割受信・終了を扱い、GUIスレッドを待機させない。
6. 出力パス予約、入力との同一性検証、ジョブ単位の置換許可を実装する。同一ディレクトリの専用一時出力を検証後に確定し、確定直前の対象変更・無許可上書きを防ぐ。再確認待ちと確定失敗を区別する。
7. 一時停止は要求受付とフレーム境界での停止完了を区別し、再開用のFFmpegストリーム・共有メモリを保持する。取消・正常終了・異常終了では子FFmpegと共有メモリを解放する。失敗時は自分の一時ファイルだけ削除し、削除失敗を記録する。NCNNの成功判定は完了通知・成果物も確認する。

## 成果物

型付きデータ、モデル登録・検証、純粋な引数生成、非同期実行制御、通知契約、出力保護、最小実行経路。

実装ファイル、工程0から確定した基盤契約、テスト内容、未検証事項、設定の再設定手順は [工程1 実装・検証記録](phase-1-results.ja.md) に記録した。

## 検証と完了条件

受け入れ条件7〜10、12〜15の基盤部分を検証する。擬似バックエンドで分割通知・起動失敗・異常終了・取消後の次ジョブ実行を確認する。一時ディレクトリで同一ファイル、重複出力、許可後の変更、確定失敗を再現し既存ファイルを保護する。

検証結果には対象環境・実施内容・結果・未解決事項を記録する。計画書の作成だけで実装や検証を完了扱いにしない。

## 対象外・共通制約

旧設定・プリセット・キャッシュの移行、互換ラッパー、恒久的な新旧GUI併存は行わない。ユーザー動画・モデル重みは削除しない。同期動画再生、キューの再起動復元、プリセット共有、複数GPU同時実行、自由な処理グラフは初版の対象外とする。
