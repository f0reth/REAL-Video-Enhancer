# 工程5: 統合・配布確認

状態: 未着手  
目安: 5〜8日  
上位仕様: [GUI全面刷新計画](../gui-redesign-plan.ja.md)

## 目的と開始条件

工程1〜4が接続され、各工程の検証結果が揃っていること。

この工程の成果を次工程へ渡す。工程間で契約を変更した場合は、上位仕様と関係する工程計画・全呼び出し元を同時に更新する。

## 作業順序

1. 受け入れ条件1〜16を通して検証し、未達項目を修正する。補間のみ、拡大のみ、復元併用、複数動画、23.976／29.97FPS、音声・字幕、10bit／HDR、途中失敗を代表ケースにする。
2. 対応OS／バックエンドで短い実機処理を実施する。未検証環境は検証表で明示し、確認済みと混同しない。
3. 1366×768、1920×1080、Windows拡大率100／150／200%と対応Linux・macOSで主要画面を確認する。キーボード・フォーカス・日本語表示も検証する。
4. 旧GUI、旧設定読み書き、旧ログ解析、不要なUI生成手順を削除する。参照検索で残存呼び出し元を確認し、新旧切替や互換ラッパーを残さない。
5. 現行配布手順を更新し、Qtモジュール・リソース・起動経路を含めてビルドする。配布物から起動し、モデル準備・短区間比較・通常出力・取消を確認する。
6. 設定の再設定、カスタムモデルの再登録、新キャッシュ規則、比較・上書き・エラー復旧の利用手順を記載する。動画・モデル重みを削除しないことを検証する。

## 成果物

検証結果表、更新済み配布手順と配布物、旧実装削除、利用手順、設定リセット案内。

## 検証と完了条件

全受け入れ条件の結果と環境を記録し、必須条件の未達を解消する。配布物で起動・処理・取消が成立する。未検証環境と既知の制約は明示し、実機検証を完了したと偽って扱わない。

検証結果には対象環境・実施内容・結果・未解決事項を記録する。計画書の作成だけで実装や検証を完了扱いにしない。

## 対象外・共通制約

旧設定・プリセット・キャッシュの移行、互換ラッパー、恒久的な新旧GUI併存は行わない。ユーザー動画・モデル重みは削除しない。同期動画再生、キューの再起動復元、プリセット共有、複数GPU同時実行、自由な処理グラフは初版の対象外とする。
